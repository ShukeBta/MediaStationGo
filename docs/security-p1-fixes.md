# P1 安全修复与升级

本次修复全仓库 Review 中的前五项 P1。其余 P2 问题仍按原清单跟进。

## Telegram Webhook 来源校验

升级后，`POST /api/telegram/webhook` 要求 Telegram 的
`X-Telegram-Bot-Api-Secret-Token` 请求头。缺失、错误、未注册、已禁用或已删除
Bot 的来源密钥均不会执行命令。每个 Bot 使用独立密钥，消息只使用对应 Bot
的通知渠道配置。

已有 Webhook 必须通过管理员的 `POST /api/admin/telegram/webhook` 接口重新注册，
提交现有 `bot_token` 和 `webhook_url`。该 Bot 必须已经配置为启用的 Telegram
通知渠道。服务会生成随机密钥，保存到数据库，再将 `secret_token` 提交给 Telegram；
管理员无需手工管理或发送密钥。请确保反向代理保留上述请求头。

重启服务或重试注册会复用已有密钥；远端注册失败不会使原有密钥失效。
数据库写入失败时不会提交新的注册请求。各 Bot 需要分别注册。密钥包含在数据库
备份中；恢复到首次注册前的备份后需再次注册。长轮询模式不受此变更影响。

## Emby 请求凭据与外部播放令牌

Emby 兼容接口不再按 IP、User-Agent 或设备 ID 恢复其他请求的登录身份。
每个请求都必须提供有效令牌，可继续使用原有的 Emby 请求头或 URL 参数。
PlaybackInfo 返回的播放地址和字幕 DeliveryUrl 仍附带 `api_key`；播放器必须
保留它，丢弃全部凭据的请求会返回 401。此变更不需要重新签发正常的登录令牌。

用途为 `external_play` 的媒体限定令牌只在原本授权的 `/api` 播放地址使用。
Emby 账号接口拒绝此类令牌以及未知用途的令牌，返回 403；正常 Emby 登录
令牌继续有效，外部播放器原有的单媒体直链仍可用。

## 当前账号权限

普通 API、管理员 API、API 配置管理和 Emby 兼容接口在授权前从数据库加载
当前角色与 tier。降级立即影响下一次请求，旧的 60 分钟访问令牌和 30 天
Emby 令牌均不能保留管理员权限；晋升也不需要重新登录。

数据库忙导致账号校验失败时返回 503 和 `Retry-After: 1`，客户端可稍后重试，
不会退回使用旧令牌中的管理员权限。

## 普通用户配置读取

`GET /api/system/config` 保留原有 `items`/键值结构，但普通用户只能读取明确
公开的语言、成人访问开关与转码能力配置。其余值统一返回 `********`，新增
配置默认不公开，避免通知、许可证、Webhook、PIN 或 URL/JSON 中的凭据泄漏。
管理员读取原值及 `/api/admin/settings` 管理功能不变。
