# P2 修复与升级说明

本次继续全仓库 Review 的第 6–19 项。前五项 P1 的修复及 Telegram Webhook
升级步骤见 [security-p1-fixes.md](security-p1-fixes.md)。

## 权限、设备和隐私

- **6：Emby 播放权限。** 媒体列表、详情、PlaybackInfo、直流、HLS、字幕和
  播放进度接口统一检查 `can_play_media`，覆盖根路径、`/emby` 和已注册的大小写别名。
  同时修复首次保存权限时 GORM 将显式 `false` 替换为 `default:true` 的问题。
- **7：设备踢出。** 新 Emby 登录令牌签入设备身份；请求头无法覆盖已签名的身份。
  Emby 和普通 `/api` 播放接口均在下一次请求时检查设备状态。旧的 30 天 Emby
  令牌没有设备绑定；只要该账号存在被踢出的设备，旧令牌须重新登录。
  普通 Web 登录令牌保持独立。此检查不会主动中断已经发送中的单个 HTTP 响应。
- **10：实时事件。** WebSocket 和 SSE 在发送每个事件前重新检查账号状态和当前权限。
  管理员可接收管理事件；普通用户仅在有下载管理权限时接收 `download`。
  扫描、刮削、转码、任务及未知主题默认不向普通用户公开。
- **11：Emby 会话。** 普通用户仅能列出自己的会话；管理员保留全部会话视图。
  已建立的令牌在角色降级后立即采用新权限。

## 刷新令牌

- **8：延迟写入与登出。** 同一用户的刷新、后台落库和登出协调执行；登出清除
  尚未落库的令牌，后台写入不能使已撤销令牌复活。登录仍保留 750ms best-effort 返回。
- **9：原子轮换。** 消费旧令牌和保存替代令牌在同一数据库事务中完成。
  并发请求最多一次成功；撤销或保存失败时回滚，不返回新凭据。PostgreSQL 通过
  用户行锁协调跨服务实例的轮换与登出，避免撤销操作遗漏并发插入的替代令牌。

## 文件与图片代理

- **12：图片代理 SSRF。** 每次连接验证 DNS 返回的全部地址，并将实际连接固定到
  已验证的公网 IP；重定向重复检查，保留原 Host 和 TLS SNI。HTTP(S) 代理通过
  CONNECT 使用已验证地址，SOCKS 同样使用固定 IP。移除缺乏同等校验的 curl 回退。
  某个公网地址连接失败时可重试同一已验证 DNS 结果中的其他地址。
- **13：目录边界。** 路径验证解析符号链接、Windows junction 和尚不存在路径的
  已有祖先，防止链接指向根目录之外。创建、重命名和删除使用 `os.Root` 限定操作。
  目录转移在写入前检查源树中的链接。
  根目录内部的绝对链接可以继续用于目录操作；重命名或删除链接本身不会误操作其目标。
- **14：递归复制。** 目录转移拒绝目标等于源目录或位于源目录内部的情况，也检查
  链接和别名，避免无限递归及磁盘耗尽。

## 播放与元数据

- **15：长时间 HLS。** 浏览器播放列表 URL 不再固定初始 JWT。hls.js 在每个请求前
  取当前令牌，原生 HLS 使用持续更新的 HttpOnly cookie，并在恢复播放时触发刷新。
  播放配置和 PIN 参数继续传递；外部播放器的媒体限定链接继续采用显式令牌。
  播放列表和分片返回 `private, no-store`，避免共用 URL 被共享缓存跨用户复用。
- **16：共享转码。** 播放器退出仅尝试回收闲置任务，不再直接终止同媒体的共享
  FFmpeg。其他观众的播放列表和分片请求持续更新活跃时间。停止接口仍校验媒体
  可见性与令牌范围；管理员强制停止及后台闲置回收保留。
- **17：NFO 演员。** 修改演员名单保留仍存在演员的完整 XML，包括角色、头像、
  属性、未知子节点、注释和同名多角色；新增、删除及排序仍按编辑结果处理。
- **18：完成状态。** Emby 详情、列表、动作返回、Resume 和 NextUp 统一使用完整
  播放历史，优先采用实际播放版本的时长，尊重 `Completed`，复用短片/长片完成规则。
  手动标记已看不再伪造未知时长；旧重复历史不会让已看条目重返 Resume。
- **19：统计事件。** `/stats/play` 缺省进度时保持续播历史不变；显式进度复用正常
  播放接口的媒体可见性、云播放授权、时长校验和完成规则，忽略客户端的 `completed`。
