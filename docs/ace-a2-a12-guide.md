# A2–A12 使用说明

本说明覆盖豆瓣补全、TMDb 季集目录、人物资料、播放统计、任务中心、轨道探测、STRM 管理、Emby 展示与播放规则、图片变体、NFO 编辑和启动进度。功能沿用现有 Media、媒体库、播放及入库架构；A1 红果短剧不在范围内，也不引入上游的 canonical 元数据重构。

**删除 STRM 目标会永久删除真实文件，无法通过媒体库回收站恢复。** 操作前必须核对预览路径；选择父目录时会删除该目录全部内容。STRM 引用和媒体库记录仍保留。

各功能的可复现验收步骤见 [A2–A12 验收清单](ace-a2-a12-acceptance.md)，本轮已执行的检查和未覆盖环境见 [本地验证记录](ace-a2-a12-validation.md)。

## 先准备资料源与权限

1. 使用管理员账号进入“管理后台 → 外部 API”（`/admin?tab=api`），配置并启用需要的 TMDb、豆瓣和 AI 服务。AI 翻译需可用的 AI 接口与模型。
2. 在“设置 → 常规”（`/settings`）设置 FFprobe 路径；程序必须能在服务端或容器内执行。路径映射同样使用服务进程看到的路径。
3. 打开“任务中心”（`/tasks`），等待后台初始化完成，再执行扫描或维护任务。

普通用户的人物、作品、季集目录遵守媒体库和内容可见性限制。配置、统计、任务中心、元数据写入、探测及 STRM 目标读取/删除需要管理员权限。Emby 媒体库显隐是展示设置，不能代替用户媒体库权限。

## A2：选择豆瓣条目并补齐资料

在媒体详情打开“编辑元数据”，使用“搜索豆瓣候选”按标题或豆瓣 ID 查找，核对标题与年份后选择。选择只填入豆瓣 ID；点击“保存并补齐豆瓣”才会保存绑定并请求补全。

补全刷新独立的豆瓣评分、抓取时间和降级状态，同时补齐缺少的标题、简介、海报、上映日期、地区、语言、类型和演员等字段。已有手动内容保留；更换豆瓣 ID 时旧条目的豆瓣评分及抓取状态失效。豆瓣资料不完整时可以降级返回，任务失败可在任务中心查看。

豆瓣卡片支持“启用代理池”“豆瓣图片直连”和可选图片镜像。图片镜像填写 HTTP(S) 域名地址；已知豆瓣图片地址会规范化，补全成功也会清除相应失败图片缓存，便于重新加载。

“外部 API”页的代理池支持：

| 类型 | 配置方式 | 凭据与清理行为 |
|---|---|---|
| 普通代理池 | 每行一个 HTTP(S) 或 SOCKS5 代理 | 已保存地址只显示脱敏值；原样保存脱敏行会保留认证。行首加 `!` 表示强制替换该行，包括移除旧认证 |
| Resin 代理池 | 实例地址、`RESIN_PROXY_TOKEN`、可选粘性标识 | 地址只接受 HTTP(S) origin；Token 加密保存且不回显，输入框留空保留已有值 |

普通代理池当前使用首个节点，失败后恢复直连。“检测不可用代理”区分可用、确定不可用和无法判定；仅在确认清理后删除检测为不可用的节点，检测本身不删除。清理使用本次检测生成的凭证，过期或池内容改变后需要重新检测。Resin 由服务端调度内部节点。

## A3：补齐完整季集目录

已匹配 TMDb 的剧集详情和整剧详情显示“完整季集目录”。管理员点击“更新 TMDb 目录”启动后台刷新；可以在任务中心跟踪。展开某季可查看播出日期、已收录数量，以及上次/下次复查时间。

“未收录”条目只代表 TMDb 目录信息，不创建可播放媒体或下载任务。已收录链接只指向当前媒体库中对用户可见的条目。TMDb 暂时返回 404 时保留本地文件及既有信息，稍后重试。

快照按电影、剧、季、集独立持久化；已有完整详情不会被后来不完整的摘要覆盖。自动复查只补齐本地单集空缺的标题、简介、播出日期和剧照。

| 该季的播出日期情况（UTC） | 再次复查间隔 |
|---|---|
| 近 30 天播出，或未来 30 天内将播出 | 1 天 |
| 日期未知，或较远的未来 | 3 天 |
| 最近播出在过去一年内 | 10 天 |
| 更早的已播季 | 20 天 |

维护调度器每 6 小时检查到期的季集任务；“间隔”是每季的到期规则，不代表每 6 小时重抓所有季。

## A4：查看人物与翻译角色

“人物资料”（`/people`）支持姓名、原名和别名搜索；全站搜索也并列展示人物和媒体。点击人物可看头像、简介、生卒日期、出生地、职务、别名及当前可见媒体库中的作品。

媒体详情的“演职员”区域提供“补全演职员”和“AI 翻译角色”。人物详情提供“刷新 TMDb 资料”和“AI 翻译资料”。刷新作品演职员需作品已绑定 TMDb；刷新人物需该人物有 TMDb 标识。

管理员可在人物页启用“自动补全 TMDb 人物资料并通过已配置 AI 翻译姓名、简介和角色”（设置键 `people.translation_enabled`）。默认不开启；启用后后台按批次处理，并保留原始姓名、简介和角色。角色翻译缓存包含作品上下文，避免不同作品中的同名角色串用译文。

手动编辑演员会同步人物关系，保留未移除演员的身份、角色译文及导演等职员记录；人物原名和译名不重复列为两个人。

## A5：查看播放统计和请求日志

“播放统计”（`/playback-stats`）提供日/周/月汇总、播放明细和当日/当周 Top 10 热榜，可按日期、用户 ID、媒体库 ID及电影/剧集筛选。日期按 UTC 分组，明细时间按浏览器本地时间展示。

同一播放会话只计一次。时长超过 10 分钟的作品，播放进度位置达到 60 秒才计数；其他或未知时长作品门槛为 20 秒。这里判断的是客户端报告的播放位置，不等于连续观看时长。手动标记已看和自动标记前集不增加真实播放次数。

“播放器请求日志”（`/player-request-logs`）显示 Emby 兼容接口的路由模板、方法、状态、耗时、来源及允许的参数。支持日期、路由、方法、状态码筛选和分页，首页可每 5 秒刷新。日志保留约 30 天，后台每天清理一次；队列繁忙时会显示未写入条数。

请求日志不保存 Token、Cookie、Authorization、完整原始 URL、请求正文或响应正文。日志用于请求诊断，不是视频内容记录。

## A6：从任务中心执行与追踪工作

“任务中心”（`/tasks`）集中展示启动进度、后台运行状态、转码、下载、字幕/导入等任务，以及以下入口：

- **任务目录与手动执行**：查看周期和当前状态，点击“执行一次”。同一任务运行时不会重复启动；手动执行仍沿用任务自身的配置条件。
- **执行历史与每日日志**：按日期、类型和状态筛选历史，点击“查看日志”定位单任务。历史每页 25 条，日志每页 50 条，日期按 UTC 分组。
- **待刮削媒体**：按媒体库筛选、重试刮削；STRM 条目的“删除目标”使用与详情页相同的预览确认流程。

任务历史持久化后可跨重启查询。重启时尚处于运行状态的历史执行会标记为“服务重启，任务执行已中断”；持久化历史本身不会盲目重放工作，各业务模块仍按自己的恢复机制运行。“定时任务”（`/scheduler`）入口继续可用。

任务日志会移除原始 HTTP(S) URL，并对常见凭据字段及 Bearer 值脱敏。

| 后台工作 | 任务名或触发入口 | 运行条件 |
|---|---|---|
| 豆瓣补全 | `douban_enrichment`，24 小时周期 | 已绑定豆瓣的适用媒体；成功后 24 小时内不重复补全 |
| TMDb 季集复查 | `tmdb_episode_recheck`，6 小时检查一次 | 按各季持久化到期时间领取任务 |
| TMDb 快照回填 | `tmdb_snapshot_backfill`，24 小时周期 | 为缺少快照的已匹配媒体补资料 |
| 人物自动资料/翻译 | 人物页自动开关；后台每分钟检查 | 开关开启且 AI 可用，按批次处理待办 |
| 媒体轨道回填 | 媒体库列表“补齐媒体轨道” | FFprobe 可执行，媒体或映射目标可访问 |
| 播放器日志清理 | 日志服务内部每日执行 | 清理超过 30 天的请求日志 |

## A7：探测轨道与设置 STRM 路径映射

媒体详情的管理员操作中选择“探测媒体轨 (ffprobe)”刷新单项；媒体库列表点击“补齐媒体轨道”批量回填，进度到任务中心查看。完整视频、音频、字幕轨道文档与技术字段持久化，重扫不会以 NFO 的简略信息覆盖已完成的探测结果。

“设置 → 常规”提供 `ffprobe.path`、`ffprobe.max_concurrent`（默认 1）和 `ffprobe.path_mappings`。映射每行采用 `URL 前缀 => 本机绝对目录`，例如：

```text
https://media.example.com/d/影视 => /mnt/media
```

上述配置将该 URL 前缀下的相对路径映射到服务端 `/mnt/media`。Windows 可将右侧写为服务可访问的绝对目录，例如 `D:\Media`。最长完整路径前缀优先；拒绝 `..` 路径穿越和逃出映射根的符号链接。本地映射文件不可用时仍尝试远程探测。

映射不修改实际播放 URL、STRM 内容或下载设置。A8 也使用这份显式映射判定远程 STRM 对应的本地可删除目标。

## A8：核对并删除 STRM 的真实目标

管理员在 STRM 媒体详情的“STRM 实际目标”中查看引用，点击“预览并删除目标”。也可从任务中心待刮削列表打开同一操作。

1. 系统读取当前 STRM 内容，将本地路径或显式 URL 映射解析为可信目录内的真实媒体文件。
2. 核对弹窗中的完整路径。默认只删除该文件；只有允许时才提供“同时删除父目录及其中的全部文件”。
3. 勾选确认框后点击“永久删除”。切换到父目录删除会要求重新勾选确认。

不允许删除磁盘根、配置的可信根目录、逃出根目录的链接、非媒体目标或 STRM 自身。父目录包含 STRM 引用时不提供目录删除选项。目标在预览后发生变化会拒绝操作，需重新打开预览。

成功后只移除已确认的真实目标，保留 `.strm` 文件和媒体库记录；这些引用可能暂时无法播放，后续可修复来源或单独管理引用。

## A9：调整 Emby 展示与播放规则

管理员在媒体库页面打开“Emby 媒体库展示”，拖拽排序、移至顶部或隐藏入口，保存至 `emby.library_display`。未配置的新库按默认顺序追加。该配置影响 Emby 兼容客户端展示；授权仍由用户媒体库权限控制。

“设置 → 常规”的“看完剧集后自动标记本季前集”（`playback.auto_mark_previous_episodes`）默认关闭。开启后，完成一集会将同库、同剧、同季且当前用户可见、存在播放路径的前面剧集标记已看。已完成条目的时间保留，不跨季/跨库，也不增加播放统计。

进度记录采用 A5 所述 60 秒/20 秒门槛。时长达到 10 分钟的作品在进度达到 90% 时判定完成；较短作品剩余不超过 30 秒时判定完成。

自动多 Part 识别支持同目录文件名末尾的 `CD`、`DVD`、`Part`、`PT`、`Disc`、`Disk` 加正整数或 `A`–`D`，例如 `Example Part1.mkv` 与 `Example Part2.mkv`。至少有两个不同编号、且编号不重复才组成一组。扫描和增量新增/删除会刷新分组；已有手动聚合或版本分组优先保留。

## A10：请求裁剪图片和 WebP 缓存

图片变体沿用现有 Web/Emby 图片地址，无需另外部署图片服务。在已有可访问图片 URL 上追加以下参数；原有鉴权仍然适用。

| 参数 | 取值 | 效果 |
|---|---|---|
| `width` / `maxWidth` | 1–4096 | 限制输出宽度，保持比例；同时出现时取较小值 |
| `height` / `maxHeight` | 1–4096 | 限制输出高度，保持比例；同时出现时取较小值 |
| `fillWidth` + `fillHeight` | 各 1–4096，必须成对 | 按指定比例居中裁切，再缩放；不放大小图 |
| `quality` | 1–100 | 编码质量；实际沿用缓存策略限制在 35–95 |
| `format` | `jpeg`、`jpg`、`png`、`webp` | 指定生成格式；`jpg` 等同 `jpeg` |

例如，已有图片地址追加 `&fillWidth=300&fillHeight=450&format=webp&quality=80` 可生成海报比例的 WebP。原地址没有查询串时用 `?` 开始。参数名不区分大小写；同名参数重复、尺寸越界、格式不支持或仅填写一个 fill 参数返回 400。

需要生成变体且未指定格式时沿用 JPEG；没有变体参数时沿用原图。支持 JPEG/PNG 的 EXIF 方向；PNG/WebP 输出保留透明度，JPEG 使用白底。GIF 和检测到的 APNG/动画 WebP 原样返回，以保留动画，因此不强制转换为请求的静态格式。

变体按来源、源文件修改时间/大小和参数分组缓存，源图变更后使用新缓存键；清理沿用现有图片缓存机制。同一变体并发请求合并，最多同时生成两个变体，输入限制为 32 MiB、3200 万像素。

## A11：在界面中编辑并写回 NFO

媒体详情“编辑元数据”支持单项编辑；整剧详情支持整剧编辑。界面可修改标题、简介、图片、日期、评分、类型、语言、地区、演员、外部 ID 和成人标记，单集还可编辑单集标题及季集号。

底部“同步写入本地 NFO”展示将更新或创建的路径。已有 NFO 时默认勾选；新建 NFO 需勾选后保存。取消勾选则仅保存媒体库元数据。无法解析合法的本地 NFO 目标时，界面提示可仅保存数据库内容；文件权限不足会在保存时报错。

- 电影更新匹配的电影 NFO；单集写 `episodedetails`；整剧写 `tvshow.nfo`。
- 保留未编辑字段、演员角色、技术轨道、注释和自定义 XML 标签；编辑某个字段时同步处理其已知旧别名，避免重扫恢复旧值。
- 单集 NFO 的外部 ID 表示单集，界面中现有 Media 的外部 ID 表示整剧，不把整剧 ID 写进单集 `uniqueid`。
- 文件必须是可信本地库内的普通文件，大小不超过 16 MiB；拒绝符号链接 NFO、无效 XML 或不匹配的根元素。
- 单次保存使用临时文件替换和数据库事务；写文件失败会回滚数据库，后续提交失败会尝试恢复原文件。若文件已被其他程序改写，则保留较新的内容并报告回滚冲突。

这里沿用现有单项与整剧编辑架构，不提供独立的季级 canonical 对象编辑。整剧界面逐项保存；其中一项失败时，先前已成功保存的项不会被整个批次回滚。

## A12：查看启动状态与扫描排队

任务中心和定时任务页面显示初始化阶段、阶段耗时、总耗时、已发现/已监听目录数及脱敏警告。HTTP 已开始监听不表示后台已准备完成；启动状态为 `ready` 后才能执行受保护的手动任务。

初始化期间相关接口返回 `503`、`code: startup_not_ready` 和 `Retry-After: 3`。定时任务等初始化流程完成后启动，关闭服务时取消任务并等待退出。

本地媒体库扫描共享串行入口。手动请求遇到已有本地扫描时返回 `409` 且 `queued: false`，表示本次请求没有排队；稍后重试。自动添加目录和 STRM 刷新等扫描会等待可用入口。云盘入库继续沿用原有按目标控制的并发规则。

目录监听只遍历目录，跟随符号链接时保留逻辑路径并避免循环；磁盘离线、根目录不可读或链接目标失效时保留已有媒体。监听新增的非空目录会增量扫描其子树，失败的监听注册可在后续刷新中重试。

## SQLite、PostgreSQL 与现有模块

两种数据库驱动继续保留，无需为了 A2–A12 切换数据库。新增模型由现有迁移流程管理；TMDb 快照、探测文档和任务快照以 JSON 文本存储，不依赖 PostgreSQL `jsonb`。通用写入使用参数绑定和跨方言冲突处理；日期聚合按方言分别生成 SQLite/ PostgreSQL 表达式，并统一到 UTC。

同路径媒体并发入库采用冲突后读取已有行，避免 PostgreSQL 唯一键冲突破坏当前事务。探测结果和 TMDb 复查有来源/身份校验；编辑元数据、豆瓣绑定与人物关系采用局部更新，避免整行零值覆盖其他功能维护的字段。

既有云盘驱动、下载器、PT、订阅、转码、播放权限及软链接/离线磁盘处理继续使用原实现。跨数据库、Windows/Linux 和第三方客户端的实际通过情况以 [验收记录要求](ace-a2-a12-acceptance.md#记录实际验证结果) 为准；本说明不把代码存在等同于环境已验证。
