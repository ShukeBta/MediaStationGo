# 剧集刮削校验与一次性维护

## 共用流程

`POST /api/media/scrape/preview` 使用与写入相同的季集校验器，只读媒体、作品及季详情，不写数据库、不访问云盘文件接口。请求包含 `media_ids`、`match`；维护工具应指定 `automatic_selection: true`，要求路径作品身份也通过校验。手动界面允许用户明确选择作品，但仍验证季集存在性。

每项结果包含路径、解析证据、有效映射、失败原因及 `revision`。写入请求通过 `match.expected_revisions` 携带每个媒体的预览版本；缺少版本或媒体已变化则拒绝。写入事务另行锁定并检查读取后的版本变化。

## 多集与分段

- `episode_num`：起始集号。
- `episode_end_num`：连续覆盖的结束集号，0 表示单集；最多覆盖 31 集。
- `episode_part_num`：分段序号，0 表示未分段，1–99 表示明确分段。
- 合并集逐集检查 TMDB 详情，任何一集缺失都不写入；单文件保留同一媒体 ID，标题包含覆盖的各集名称。
- 分段仍是独立可播放文件，不做物理合并、不自动连续播放、不去重删除。不同分段及覆盖范围不得合并为清晰度版本；相同覆盖范围的不同清晰度可以共存。
- 非连续集号、小数编号、合并/分段文件不自动猜测，需用户明确指定。此版本不为非标准编号创建虚假的 TMDB 集号。
- 旧记录字段默认 0。模型迁移新增字段；版本索引触发器及重建输入包含这两个字段。Web 显示覆盖范围和分段序号；Emby 单文件合并集提供 `IndexNumberEnd`。

## 一次性客户端

`dev/scrape_validated_groups.py` 只调用服务预览/应用接口，不复制解析算法，不直接连接数据库或 TMDB。输入按剧分组，每组提供媒体 ID 和所选作品。身份不明确的剧必须先查明，不由脚本选择搜索第一名。

令牌从 `MEDIASTATION_TOKEN` 环境变量读取。`--base-url` 指定服务器基址，`--input` 指定分组 JSON，`--output-dir` 必须是新目录。默认仅预览；只有 `--apply` 才写入通过服务端校验的项。逐组保留预览、API 旧值快照、结果和回读数据。部分失败立即停止，不重试，不删除文件。

客户端依赖新预览接口；旧服务不支持时必须报错停止，不能回退到历史独立 SQL 写入脚本。旧的一次性维护草稿未被自动替换或删除。

## 验证边界

本地测试使用模拟 TMDB 和 SQLite。生产 PostgreSQL 迁移、真实浏览器操作、各 Emby 客户端的范围展示及分段播放未在生产验证。本次变更不包括生产发布；不能据本地测试通过直接宣称线上已修复。
